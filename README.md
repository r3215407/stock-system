# Glacier Signal

Glacier Signal 是一个面向 A 股与场内基金的趋势回调转强评估工具。系统读取真实前复权日线，执行硬性过滤与评分，并根据账户风险约束计算计划仓位和结构止损。

## 本地开发

要求：Node.js 20 或更高版本。

```bash
npm ci
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。

## 验证

```bash
npm run lint
npm run build
```

## Vercel 定时任务

生产环境需要配置 transaction pool 模式的 `POSTGRES_URL`（有直连或 session 模式地址时可同时配置 `POSTGRES_URL_NON_POOLING`，仅用于运维）和至少 16 位随机值的 `CRON_SECRET`。应用运行时优先使用 pooled URL，单实例最多保持 2 条连接。全市场扫描任务、分片进度与最终结果全部保存在 PostgreSQL，不依赖 Redis。

- ETF 轮动：北京时间周一至周五 14:45，成功、失败或工作日休市时按现有规则发送邮件；周末不查询、不发邮件。
- 全市场扫描：交易日由用户打开页面并点击按钮启动，不发送邮件。
- 扫描 worker：由打开扫描页面的浏览器逐个触发 PostgreSQL 分片；页面关闭后暂停，再次打开并恢复任务后继续。

Vercel 只保留 ETF 轮动这一个每日 Cron。全市场扫描不依赖 Cron，实际扫描需要用户打开页面并点击扫描按钮。Free/Hobby 的 Cron 是小时级精度，因此 ETF 任务也不能保证严格在配置分钟触发。中国交易所休市日会在接口内再次拦截。

`POST /api/screenings` 只创建 PostgreSQL 任务并立即返回 `202`；证券池和基准行情由浏览器发起的第一个工作单元读取。初始化任务与股票分片都有租约和最多三次重试。卡在“获取证券池”的任务会自动迁移为待初始化状态；重新点击扫描按钮即可返回并继续。

浏览器在任务运行期间串行调用 `/api/screenings/:jobId/work`，每次只领取一个 PG 工作单元，并对临时网络或数据库故障退避重试。任务编号保存在当前浏览器中，刷新或重新打开页面可恢复；关闭页面时当前工作单元可能完成，但不会继续领取下一个分片。

每个分片会单独保存本轮失败的证券子集。扫描完成后如果仍有“数据失败”，再次点击按钮只会重新排队失败证券；已经成功评分的结果和正常排除项不会重新请求，重试结果完成后与原结果合并。

服务端分片并发可通过 `SCREENING_SECURITY_WORKERS` 调整。浏览器驱动的全市场扫描固定使用 3 个工作线程，并将腾讯行情请求起始间隔限制为至少 900 毫秒；公开行情源出现限流时不要为了缩短等待时间提高频率。

## 项目结构

- `app/`：Next.js 页面与行情 API
- `components/`：Hero、评估工作台及通用界面组件
- `lib/`：评分规则、行情读取与指标计算
- `public/assets/`：正式 Hero 视觉资产
- `design.md`：Glacier 全站设计规范
- `landing-hero-design.md`：Hero 设计规范
- `趋势中的回调转强交易模型.md`：交易模型规则来源
- `趋势回调转强评分页面-PRD.md`：评分产品需求文档

## 数据与边界

行情来自公开市场数据接口，页面会显示实际数据来源和复权口径。评分表示当前条件与模型的匹配程度，不代表上涨概率，也不构成投资建议。产品不连接券商，不自动下单。
